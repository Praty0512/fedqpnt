--- Detector bug-fix round (D-022) -- ROOT CAUSE FOUND AND FIXED ---
Bug 1 (features.py): outage/invalid-fix epochs zeroed x4-x7/x11 (mean_cn0, std_cn0, cn0_rate,
  agc, nsat_delta) even though GnssReceiver.solve populates these on an invalid fix -- this
  discarded the strongest jamming evidence. Fixed: only x1/x2/x3/x8/x9/x10 are zeroed when
  genuinely unavailable (no fit / NaN raim / NaN clk).
Bug 2 (pseudolabel.py): the "agc >= 6dB" rule assumed AGC RISES under jamming; this codebase's
  Jamming model (and GnssFix.agc_db convention) has AGC DROP under jamming. The rule never
  fired on jamming (0/21 epochs verified). Fixed to |agc| >= 6dB.
Bug 3 (tests/_trust_harness.py): invalid-fix epochs were dropped entirely from train/eval,
  compounding bugs 1+2 (only mild, clean-looking jamming epochs survived). Fixed: kept.
Effect: jamming AUC 0.430 -> 0.773 (CI [0.702,0.845]). Overall AUC 0.688 -> 0.727 (CI
[0.700,0.755]).

Meaconing AUC 0.267 -> 0.246, CI [0.194, 0.301] -- STILL significantly below chance, but
DIAGNOSED as a pseudo-label rule blind spot, not a code bug: MeaconingReplay's delay is
degenerate with the clock-bias unknown (absorbed after 1 epoch), so nis_pos/raim/resid_rms
are statistically indistinguishable from clean for the rest of the 60s attack (verified:
active vs clean means 0.53/0.45, 1.33/1.36, 1.95/1.98 respectively). Only the single onset
clk_jump transient is caught by the current y=1 rules (h1/agc/raim/clk_jump), so ~95% of
active epochs get pseudo-labelled negative -- teaching the detector the wrong association.
Two features DO carry a real, learnable steady-state signature the current rules don't use:
x4 cn0_mean (+0.47 active vs -3.48 clean, the +4dB replay power bump) and the NEW x14
